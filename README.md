# CoalGuard – AI-Based Smart Governance and Compliance Monitoring System for Coal Mines

SIH 2026 project. **React (Vite)** frontend on Vercel · **Node.js/Express** API on Render · **MongoDB Atlas** database.

**Honesty notes**
- All sensor values are **simulated demonstration data**.
- The "AI" on the Compliance page is a **rule-based engine** with configurable thresholds. No trained model is connected.
- PDF download uses the browser print window (choose "Save as PDF"). CSV is generated by the backend.

## What was wrong with the deployed site (and what was fixed)
| Problem | Fix |
|---|---|
| Login showed "Request failed" on Vercel: the frontend called a relative `/api`, which only works with the local Vite proxy. On Vercel that hits Vercel itself, not your backend. | `frontend/src/api.js` now uses `VITE_API_URL`. Local development still uses the Vite proxy. |
| If MongoDB could not be reached the backend **silently switched to a local file** (lost on every Render restart). | In production MongoDB is required. If it is down, every API call returns a clear **503** message and `/api/health` explains the problem. The JSON file is allowed only for local development with an empty `MONGODB_URI`. |
| CORS allowed every website. | `CORS_ORIGINS` allow-list (supports `https://*.vercel.app`). |
| A network hiccup on refresh logged the user out. | Only a rejected token (401) logs out. Other errors show "Try again". |
| The server only started listening after the database connected, so failures were invisible. | Server starts first; database connects in the background and retries every 10 s. |
| Any logged-in user could read the full activity log. | `/api/activity` is now admin only. |
| No limit on login attempts. | Rate limits on login, register and the contact form. |
| `backend/.env` was inside the ZIP. | Removed. Only `.env.example` files are included. `.gitignore` blocks `.env`. |
| Refreshing `/about` or `/login` on Vercel would give a 404. | `frontend/vercel.json` rewrites all paths to the app. |
| Demo accounts missing if the database already had other users. | The three demo accounts are created if missing (never overwritten). |

Design, pages, charts and features are unchanged. The only UI additions are the clearer error messages and a "Try again" box.

# Step-by-step guide (beginner friendly)

## Part 1 – Open the project in VS Code
1. Right-click `Coal-Mine-Governance-System.zip` → **Extract All**.
2. Open VS Code → **File → Open Folder** → choose the extracted `Coal-Mine-Governance-System` folder.
3. Open the terminal: **Terminal → New Terminal**.
4. Install everything (needs internet):
   ```
   npm run setup
   ```

## Part 2 – Create the MongoDB Atlas database (free)
1. Go to https://www.mongodb.com/cloud/atlas and sign in. Create a free **M0** cluster.
2. **Database Access** → *Add New Database User* → choose a username and a password (use letters and numbers only, to keep it simple). Give it *Read and write to any database*.
3. **Network Access** → *Add IP Address* → **Allow access from anywhere (0.0.0.0/0)**. Render needs this.
4. **Database** → *Connect* → *Drivers* → copy the connection string. It looks like:
   `mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`
5. Replace `<user>` and `<password>` with yours, and add the database name before the `?`:
   `mongodb+srv://myuser:mypass@cluster0.xxxxx.mongodb.net/coalguard?retryWrites=true&w=majority`
   Keep this text private. You will paste it into Render (and, for local tests, into `backend/.env`).

## Part 3 – Run it on your computer
1. In VS Code, copy `backend/.env.example` to a new file `backend/.env` (right-click → Copy, Paste, rename).
2. Open `backend/.env` and set:
   - `JWT_SECRET=` a long random text. Generate one by running: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
   - `MONGODB_URI=` your Atlas string from Part 2 (or leave it empty to test with a local file only).
3. Terminal 1 – start the backend:
   ```
   npm run backend
   ```
   You should see `Database: MongoDB connected` and `Seeding demonstration data...` (first start only).
   Open http://localhost:5000/api/health – it must show `"ok":true` and `"status":"ready"`.
4. Terminal 2 (click `+` in the terminal panel) – start the frontend:
   ```
   npm run frontend
   ```
   Open http://localhost:5173. (Locally you do **not** need `VITE_API_URL`.)
5. Test the logins from the table above. Use **Logout** (top right) between accounts.
6. Optional automatic test of every API (backend must be running; Node 18+):
   ```
   npm run test:api
   ```
   It prints PASS/FAIL for about 44 checks. Test your deployed backend with:
   `API_URL=https://YOUR-BACKEND.onrender.com npm run test:api` (on Windows PowerShell: `$env:API_URL="https://YOUR-BACKEND.onrender.com"; npm run test:api`).

## Part 4 – Put the code on GitHub
Render and Vercel both deploy from GitHub. Create a GitHub repository and push the project (VS Code → Source Control → *Publish to GitHub*). `.env` files are ignored automatically; check that no `.env` appears in the list of files before you commit.

## Part 5 – Deploy the backend on Render
1. https://render.com → **New + → Web Service** → connect your GitHub repository.
2. Settings:
   - **Root Directory:** `backend`
   - **Runtime:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Health Check Path:** `/api/health`
3. **Environment** → add these variables:

   | Name | Value |
   |---|---|
   | `NODE_ENV` | `production` |
   | `MONGODB_URI` | your Atlas connection string |
   | `JWT_SECRET` | long random text (32+ characters) |
   | `CORS_ORIGINS` | `https://coal-mine-j6sb.vercel.app` (add `,https://*.vercel.app` to also allow Vercel preview links) |
   | `SEED_DEMO_DATA` | `true` (creates the demo accounts and sample mines on first start) |

   (A `render.yaml` Blueprint is included if you prefer *New + → Blueprint*; you still must type `MONGODB_URI` and `CORS_ORIGINS` in the dashboard.)
4. Click **Create Web Service**. When it says *Live*, open `https://YOUR-BACKEND.onrender.com/api/health`. You want `"ok":true`.
   - If it shows 503, read the `problem` text. Most common: wrong password in `MONGODB_URI`, or Atlas *Network Access* does not allow `0.0.0.0/0`.
5. Free Render services sleep when idle. The first request after a break can take about a minute. The website shows a clear message if that happens.

## Part 6 – Connect your Vercel website to the backend
1. Vercel → your project → **Settings → Environment Variables** → add:

   | Name | Value | Environments |
   |---|---|---|
   | `VITE_API_URL` | `https://YOUR-BACKEND.onrender.com` (no slash at the end, no `/api`) | Production (and Preview) |

2. Make sure the project's **Root Directory** is `frontend`, Framework **Vite**, Build `npm run build`, Output `dist`.
3. **Deployments → ⋯ → Redeploy.** (Vite reads the variable at build time, so you must redeploy after adding or changing it.)
4. Open https://coal-mine-j6sb.vercel.app/login and log in with a demo account.

## Redeploying after changes
- Change code → commit and push to GitHub → Render and Vercel redeploy automatically.
- Change only an environment variable → in Render it restarts on save; in Vercel you must click **Redeploy**.

## Troubleshooting
| Message | Meaning / fix |
|---|---|
| "The website is not connected to a backend…" | `VITE_API_URL` is missing in Vercel. Add it and redeploy. |
| "Cannot reach the backend server…" | Backend asleep/not running, wrong `VITE_API_URL`, or `CORS_ORIGINS` does not include your Vercel address. Test `/api/health` in the browser. |
| "The server did not return a valid response (HTTP 404)" | `VITE_API_URL` points to the wrong address (for example to the Vercel site itself). |
| "The database is not connected…" (503) | See the reason in the message: password, Atlas Network Access, or missing `MONGODB_URI`. |
| Render log: `FATAL: JWT_SECRET…` | Set a long `JWT_SECRET`. |
| Wrong email or password for a demo account | The demo accounts are created when the database is empty or missing them. Check the Render log for "Seeding demonstration data" or "Created missing demo account". |
| Port 5000 in use (local) | Change `PORT` in `backend/.env` and the proxy target in `frontend/vite.config.js`. |

## Project layout
```
backend/   Express API: config/db.js (MongoDB), middleware/ (auth, CORS, rate limit, errors), controllers/, routes/api.js,
           models/ (data layer), utils/ (compliance rules, seed), scripts/smoke-test.js
frontend/  React + Vite: src/api.js (API client), auth.jsx, pages/ (public site, Login, Dashboard, Monitoring,
           Compliance, Reports, Admin), vercel.json
render.yaml  Optional Render blueprint
```

## Main API routes (all under /api; JWT in `Authorization: Bearer <token>`)
`GET /health`, `GET /public/stats`, `POST /public/contact`, `POST /auth/register`, `POST /auth/login`, `GET /auth/me`, `GET|PATCH|DELETE /users` (admin),
`GET|POST|PUT|DELETE /mines`, `PATCH /mines/:id/approval`, `POST /mines/:id/inspect`, `GET|POST /sensors`, `POST /sensors/simulate`,
`POST /compliance/check`, `GET /compliance/summary`, `GET|PATCH|DELETE /alerts`, `GET|POST|PATCH /grievances`, `GET /dashboard/stats`,
`GET /reports/:type?format=csv`, `GET /activity` (admin).

## Settings (environment variables)
See `backend/.env.example` and `frontend/.env.example`. Thresholds: `METHANE_WARN`, `METHANE_CRIT`, `PM10_WARN`, `PM10_CRIT`, `TEMP_WARN`, `PPE_MIN`.
