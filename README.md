# CoalGuard – AI-Based Smart Governance and Compliance Monitoring System for Coal Mines

SIH 2026 project. React frontend + Node.js/Express REST API + MongoDB (or a local JSON file if MongoDB is not installed).

**Important honesty notes**
- All sensor values are **simulated demonstration data**.
- The "AI" on the Compliance page is a **rule-based engine** (configurable thresholds). No trained AI model is connected.
- PDF download uses the browser print window (choose "Save as PDF"). CSV is generated by the backend.

## What is inside
```
Coal-Mine-Governance-System/
  backend/   Express API (config, controllers, models, routes, middleware, utils, server.js)
  frontend/  React (Vite) app: public site (Home, About, Features, How it works, Safety standards, FAQ, Contact), Login, Dashboard, Monitoring, Compliance, Reports + Admin panel
  package.json  helper scripts
```

## Run it in VS Code (Node.js already installed)
1. Download `Coal-Mine-Governance-System.zip`.
2. Right-click it and choose **Extract All** (or unzip).
3. Open VS Code → **File → Open Folder** → select the extracted `Coal-Mine-Governance-System` folder.
4. Open the terminal: **Terminal → New Terminal**. It should be inside `Coal-Mine-Governance-System`.
5. Install everything (run this first, it needs internet once):
   ```
   npm run setup
   ```
6. The file `backend/.env` is already included. Leave `MONGODB_URI=` empty to use the JSON file fallback (data saved in `backend/data/db.json`).
   To use MongoDB, install it and set `MONGODB_URI=mongodb://127.0.0.1:27017/coalguard`. If MongoDB cannot be reached, the app automatically falls back to the JSON file and prints a message.
7. Start the backend (run second, keep this terminal open):
   ```
   npm run backend
   ```
   Backend URL: http://localhost:5000 (health check: http://localhost:5000/api/health). On first start it creates demo data.
8. Open a **second terminal** (click the `+` in the terminal panel) and start the frontend:
   ```
   npm run frontend
   ```
   Frontend URL: http://localhost:5173
9. Open http://localhost:5173 in your browser.

## How to test each part
- **Login:** use a demo account. Admin goes to Dashboard, Operator to Monitoring, Inspector to Compliance. Use Logout at the top.
- **Dashboard:** KPI cards and charts load from the API and refresh every 10 seconds.
- **Monitoring:** pick a mine, click **Simulate readings** or **Start live simulation**, or type a reading. Enter methane `1.5` and save: a Critical alert appears. Register a mine as Operator, then approve it as Admin.
- **Compliance:** click **Run compliance check**. Open alerts show reason, severity, recommended action and date. Filter, resolve or reopen them.
  Rules: methane above warning/critical limit, PM10 air quality above limits, temperature, water pH, PPE below minimum, inspection overdue.
- **Reports:** choose a report, search, **Download CSV**, or **Download PDF** (print dialog). Submit a grievance; as Admin, set status and write a response.
- **Admin panel (Admin only):** approve mines, change user roles, disable or delete users, read the audit log.

## Role permissions
- **Admin:** everything, including mine edit/delete, approvals, users, grievance responses.
- **Operator:** sees only their own mines, registers mines (pending approval), submits readings and grievances.
- **Inspector:** sees all mines, runs compliance checks, starts/completes inspections, resolves alerts.

## Main API routes (all under /api, JWT in `Authorization: Bearer <token>`)
`POST /auth/register`, `POST /auth/login`, `GET /auth/me`, `GET|PATCH|DELETE /users`, `GET|POST|PUT|DELETE /mines`, `PATCH /mines/:id/approval`, `POST /mines/:id/inspect`,
`GET|POST /sensors`, `POST /sensors/simulate`, `POST /compliance/check`, `GET /compliance/summary`, `GET|PATCH|DELETE /alerts`, `GET|POST|PATCH /grievances`,
`GET /public/stats`, `POST /public/contact` (public contact form, saved in the `contacts` collection), `GET /dashboard/stats`, `GET /reports/:type?format=csv`, `GET /activity`.

## Settings in backend/.env
`PORT`, `JWT_SECRET`, `MONGODB_URI`, and the thresholds `METHANE_WARN`, `METHANE_CRIT`, `PM10_WARN`, `PM10_CRIT`, `TEMP_WARN`, `PPE_MIN`. Restart the backend after changing them.

## Common errors
- **`npm` is not recognized:** close and reopen VS Code, or reinstall Node.js.
- **Port 5000 already in use:** change `PORT` in `backend/.env` and the proxy target in `frontend/vite.config.js`.
- **Page shows "Cannot reach the backend":** start the backend first (step 7) and keep it running.
- **MongoDB not reachable message:** harmless; the JSON fallback is used. Clear `MONGODB_URI` to hide it.
- **Want fresh demo data:** stop the backend, delete `backend/data/db.json`, start again.
- **`npm run setup` fails:** check your internet connection and run it again.
- **Blank page after login on refresh:** make sure both servers are running.

## Not included
No real sensor hardware integration, no real AI model, no email/SMS sending. Everything runs locally with free tools.
